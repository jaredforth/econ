# `thrift doctor`: check the setup and say what to fix

Setup is the main friction (Ollama running, router model pulled, cloud creds, env keys). One command checks all of it.

**Slug:** cli-doctor
**Depends on:** `cli-serve`
**Verify:** `.venv/bin/python -m unittest tests.test_doctor -q`

## Goal
`thrift doctor` prints one PASS/FAIL line per check with the exact fix command for each FAIL; exit 1 if any FAIL.

## Context
- Ollama API: `GET {OLLAMA_HOST}/api/tags` returns `{"models":[{"name":...}]}` (reuse the host logic in `thrift.classify`; expose a helper `ollama_host()` there if one is not present).
- Router model name is `thrift.classify.ROUTER_MODEL`. Fix command for a missing model: `ollama pull <model>`.
- Tier targets: `THRIFT_SIMPLE/MODERATE/HARD` (see `tier-env-config`). If a target starts with `bedrock/`, also require `AWS_PROFILE` or `AWS_ACCESS_KEY_ID`; do not call AWS.

## Preflight
`grep -n "THRIFT_" config.yaml` hits; `thrift/cli.py` has `serve`.

## Files
- Modify: `thrift/cli.py`, `thrift/classify.py` (only if `ollama_host()` is missing)
- Create: `tests/test_doctor.py`
- Do not touch: `config.yaml`

## Requirements
1. Checks, in order: Ollama reachable; router model pulled; `.env` found; `LITELLM_MASTER_KEY` set; the three THRIFT_* tier vars set; AWS creds if any bedrock target.
2. Each check is a small function returning `(ok, fix_text)`; `doctor` only prints and sets the exit code.
3. No network calls except the Ollama GET (timeout 2s).

## Testing
unittest: with env cleared and `OLLAMA_HOST=http://127.0.0.1:9`, `main(["doctor"])` returns/exit 1 and output contains `ollama serve`; with a stubbed tags response including the router model and all env set, exit 0.

## Acceptance criteria
- [x] Tests pass
- [ ] **Human check:** on this machine the output is readable and the fixes are accurate

## Out of scope
Auto-fixing, pulling models.
